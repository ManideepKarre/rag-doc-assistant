# RAG Document Assistant

A full-stack Retrieval-Augmented Generation (RAG) app: upload a document, and ask
questions that are answered using the document's own content — with cited
source excerpts, not hallucinated guesses.

Built as a portfolio project to combine a Master's background in AI/Big Data
with practical full-stack engineering: Python, machine learning embeddings, a
vector database, and a modern React/Next.js frontend, all containerized with
Docker.

## How it works

```
  +-------------+   upload .pdf/.txt    +--------------+
  |  Next.js    | --------------------> |   FastAPI    |
  |  frontend   |                       |   backend    |
  |  (React/TS) | <-------------------- |              |
  +-------------+   answer + sources    +------+-------+
                                                |
                                chunk -> embed (sentence-transformers)
                                                |
                                                v
                                     +-----------------------+
                                     | PostgreSQL + pgvector |
                                     |  (chunks + vectors)   |
                                     +-----------------------+
```

1. **Upload**: a document is split into overlapping text chunks, each chunk is
   embedded locally with `sentence-transformers` (`all-MiniLM-L6-v2`, 384-dim),
   and stored in Postgres using the `pgvector` extension.
2. **Ask**: the question is embedded the same way, and the closest chunks are
   retrieved via cosine similarity search directly in Postgres.
3. **Answer**: the retrieved chunks are used to ground an LLM answer (OpenAI
   API, if `OPENAI_API_KEY` is set). Without an API key, the app still works —
   it falls back to returning the most relevant excerpts directly, so the
   whole project runs end-to-end with **zero paid API keys**.

## Tech stack

| Layer       | Tech |
|-------------|------|
| Frontend    | Next.js 14 (App Router), React, TypeScript |
| Backend     | FastAPI, SQLAlchemy, Pydantic |
| Embeddings  | sentence-transformers (`all-MiniLM-L6-v2`) |
| Vector store| PostgreSQL + `pgvector` |
| LLM (optional) | OpenAI API |
| Infra       | Docker, docker-compose |

## Running it

### Option A: Docker Compose (recommended)

```bash
git clone https://github.com/<your-username>/rag-doc-assistant.git
cd rag-doc-assistant
cp backend/.env.example backend/.env   # optionally add OPENAI_API_KEY
docker compose up --build
```

- Frontend: http://localhost:3000
- Backend docs (Swagger UI): http://localhost:8000/docs

### Option B: Run locally without Docker

**Backend**

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# requires a local Postgres with the pgvector extension available
cp .env.example .env
uvicorn main:app --reload
```

**Frontend**

```bash
cd frontend
npm install
cp .env.local.example .env.local
npm run dev
```

## Running the tests

The core chunking/prompt-building logic is unit tested independently of the
database and ML model so it runs instantly, anywhere:

```bash
cd backend
pip install pytest
pytest
```

## API overview

| Method | Path                | Description |
|--------|---------------------|--------------|
| POST   | `/documents/upload`  | Upload a `.pdf` or `.txt` file |
| GET    | `/documents`         | List uploaded documents |
| POST   | `/ask`               | `{ "question": "...", "top_k": 4 }` → answer + sources |
| GET    | `/health`            | Liveness check |

Full interactive API docs are auto-generated by FastAPI at `/docs`.

- Add user accounts and per-user document scoping.
- Support more file types (`.docx`, `.md`, web URLs).
- Stream answers token-by-token instead of returning the full response at once.
